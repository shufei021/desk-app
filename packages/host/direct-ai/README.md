# @deepseek-ai/dsh-direct-ai

English | [中文](README.zh.md)

## Summary

Send text directly to a configured provider without starting an Agent or Session. Stream chat text, generate images, or submit and poll an OpenAI Sora-style video job. Save provider metadata separately from API keys, recover complete request inputs and results from private history, and view generated media through authenticated owner-only URLs. Requests are never retried, because a failed connection can leave billing unknown.

## Use this package

Mount this service beside credentials, storage-domain and Connection; the browser consumer uses its generated `directAi` Remote namespace.

### Provider protocols

Chat uses OpenAI Chat Completions with `stream: true` and SSE. Images use JSON `images/generations` responses containing canonical `b64_json` or an HTTP(S) URL downloaded without Authorization. An image request carrying stored reference images uses multipart `images/edits` instead: `model`, `prompt`, one `image` part per reference in request order, an optional `mask` part, and admitted parameters as form fields; those responses are parsed exactly like generation responses. Video uses multipart `POST videos`, status `GET videos/{id}`, and `GET videos/{id}/content` after completion. These are specific protocols, not a claim of compatibility with arbitrary image or video vendors.

A service requires a nonempty name/model and an explicit base URL. HTTPS is required except on loopback; user information, query and fragments are forbidden. An optional endpoint is a same-origin relative or absolute path, without a query or fragment. Omitted endpoints resolve beneath the base URL to `chat/completions`, `images/generations` or `videos`. An optional `editEndpoint` follows the same rules and defaults to the generation path with a final `generations` segment replaced by `edits`, otherwise `images/edits`. JSON parameter objects can add ordinary model parameters but cannot override model/messages/prompt/image/mask/stream, supply credentials or enable tools, including nested tool fields.

Chat sends every supplied system/user/assistant message. Images and video require exactly one nonempty user message; other messages are rejected instead of being silently discarded. An optional `displayPrompt` records the user's own description for the submitting UI to display beside the result; provider bodies derive from `messages` and admitted parameters only. Every admitted provider run saves complete non-credential input and a service snapshot before HTTP dispatch, then saves success, failure or cancellation and any partial output. Invalid inputs, missing services and capacity refusals do not start a provider run.

### Trusted image generation

`generateImage(serviceId, prompt, signal)` is a non-Remote Host method for consumers that independently authorize spending a saved image service's credential. It accepts no caller URL, model, key or parameter override. Missing image storage, a non-image service or absent credential is rejected before HTTP submission. It shares the existing serialized service/credential snapshot, concurrency limit, cancellation, deadlines and durable direct history; shutdown waits for the entire operation. Generated bytes also enter `attachments`, and returned `GeneratedImageResult` references remain readable after direct-history media eviction. Success is returned only after the completed direct record is durable. Storage or attachment failure can follow a billable provider request and never causes a retry. Remote catalog, mutations, history, directory lookup and direct execution remain owner-only.

### Reference image edits

`uploadReference({ data, mime, name? }, signal)` is an owner-only Remote that stores one canonical base64 PNG/JPEG/WebP/GIF of at most `maxMediaBytes` in `attachments` and returns the durable reference to pass as `DirectRequest.references` or `DirectRequest.mask`. A request accepts up to eight references and at most one mask, and a reference image on a chat or video service is rejected. `run` reads every reference through the attachment store before HTTP dispatch; a reference that is no longer readable fails as `DIRECT_AI_INVALID_INPUT` without dispatch. The request record stores the references, never image bytes, so direct history stays small while the attachment library owns the pixels. Reference reads and edit responses share the per-run `maxMediaBytes` budget. `editEndpoint` selects the edit path; otherwise a final `generations` segment becomes `edits`, falling back to `images/edits`.

### Model directories

`discoverModels` reads either the fixed keyless [CrazyToken public catalog](https://www.aiyoyoo.com/api/v1/llm-pricing/models), `models` beneath a saved service's base URL with its atomically captured credential, or a draft base URL paired with its own explicit key. It rejects redirects, invalid JSON, duplicate identities, credential echoes and oversized raw or projected output. Reads share request deadlines, concurrent capacity and shutdown cancellation, but do not invoke a model, modify account groups, or add inference history. Platform, `groupId` and `groupName` annotations are display filters only and are never sent as routing parameters. The public listing contains no key permissions or protocol capability declaration; the platform homepage documents OpenAI-compatible chat, while its image/video protocols require separate verification.

The `direct_ai` store writes version 2 and accepts version 1 records with absent annotations. Opening old records does not rewrite them; subsequent edits stamp the new version. Downgrading after writing annotations or an edit endpoint is not supported.

### Limits and recovery

All limits are Schemastery plugin configuration fields, validated when the plugin loads.

| Field | Default | Meaning |
|---|---|---|
| `dshHome` | normal Harness home | Private media root override. |
| `requestTimeoutMs` | `120000` | Total chat/image deadline. |
| `videoTimeoutMs` | `900000` | Total video deadline, including polling/download. |
| `pollIntervalMs` | `2000` | Delay between successful video status reads. |
| `maxRequestBytes` | `1048576` | Complete retained input and service configuration byte limit. |
| `maxResponseBytes` | `33554432` | Accumulated HTTP JSON/SSE and retained frame limits. |
| `maxMediaBytes` | `104857600` | Aggregate generated media bytes and reference-image bytes per run. |
| `maxConcurrent` | `2` | Concurrent runs; excess requests fail without queueing. |
| `maxHistory` | `100` | Retained settled runs; active runs are not evicted. |

Provider errors are typed `DirectAiError` failures with stable `DIRECT_AI_*` codes. Error messages never contain provider bodies, keys or transport diagnostics. No request or failed status read is retried. Cancellation stops local HTTP, polling and downloads; a submitted provider job may continue remotely and may be billed. Restart marks interrupted running records cancelled rather than submitting them again. A storage failure rejects visibly; a post-success retention-cleanup failure preserves the saved completed result and emits a warning.

### Credentials and media

`save` accepts an API key only on input. Omitting it preserves the saved key; an empty value removes it. `catalog` and `save` return only `configured`, never a key or masked preview. Credentials use the credentials service; metadata and request/result history use the `direct_ai` storage domain. New homes start with no services or history.

Generated files use exclusive random names beneath `$DSH_HOME/data/direct-ai/media`, directory mode `0700` and file mode `0600` where the OS supports these modes. Only detected PNG/JPEG/WebP/GIF and MP4/WebM bytes are served inline; SVG and HTML are rejected. `GET`/`HEAD /api/direct-ai/media?id=<opaque>` is an exact authenticated owner-only Connection route, with optional `download=1`; it never accepts a filesystem path. Returned frame URLs are document-relative so proxy prefixes and Desktop delivery work. Media is deleted when its retained run is evicted.

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

The service owns admitted operations through one cancellation controller each. Disposal aborts and awaits HTTP, polling, media reads and final history writes before closing the domain. Provider streams have explicit byte accounting and reader cancellation; authenticated requests reject redirects. The implementation does not call the Agent registry, Session lifecycle, LLM waterfall or Agent telemetry paths.

[Types](src/types.ts) define the browser data; [validation](src/validation.ts) admits configuration and JSON; [protocols](src/protocol.ts) own external responses; [storage](src/storage.ts) declares the versioned domain; [the service](src/index.ts) owns authorization, credentials, retention and private media. [Protocol tests](tests/protocol.spec.ts) use real loopback HTTP, and [service tests](tests/service.spec.ts) boot real Loader compositions with JSON storage, credentials and Connection.

<a id="model-experience"></a>
## Model Experience

### Direct provider request

#### What the model sees

The selected chat model receives exactly the supplied textual `messages`, selected `model` and admitted JSON parameters; no Harness system prompt, tools, skills, Session context or Agent data is added. Image/video generation receives the single user prompt and admitted parameters. API keys authenticate HTTP and are not part of model input.

#### Token effect

The provider owns tokenization, generation cost and billing. This service adds no prompt tokens and does not collect Agent token accounting. Complete input and result history remain local to this feature unless the owner explicitly copies them elsewhere.

#### KV Cache effect

The service neither creates nor controls a provider cache. Repeated identical chat prefixes may qualify for provider-side reuse; model, message or parameter changes can prevent reuse. Each run is independent and never automatically appends history to a later request.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

These constraints delimit the supported first-version protocols and security scope.

- Provider-specific extensions, chat tools, chat prompt attachments, reasoning-only output, video reference images and arbitrary vendor protocols are not supported. Chat supports one completion (`n: 1`); multiple alternatives are rejected rather than combined.
- Media delivery supports one byte range, including open-ended and suffix ranges; multipart range requests receive HTTP 416.
- Credentials and input/history are private to authenticated owner access, not protected from the same OS account, trusted Host plugins, backups or a compromised Host. The local credential provider stores keys on disk, and trusted in-process code can call `readRecord`.
- Process loss can interrupt final output persistence. The pre-dispatch input remains saved; restart records interruption, without asserting whether the remote provider finished or billed it.
- Credential replacements use immutable private references committed with service metadata. A failed save keeps the previous callable pair; a failed metadata commit can leave an unreachable credential record. Cleanup failures are logged and never restore a deleted service or key.
- Provider status progress is not a billing or completion guarantee. Real provider compatibility requires with-key checks owned by the integrating application; package tests are keyless loopback protocol fixtures.
